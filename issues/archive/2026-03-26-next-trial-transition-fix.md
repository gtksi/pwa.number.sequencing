# 次の問題へ進まない不具合の修正

## 概要
1問クリアしたあと、画面の状態が「アイドル状態（idle）」のまま停止し、次の問題へと自動進行しない不具合を修正しました。

## 原因
直前に行った「PixiJS ドラッグ操作から React DOM タップ操作への全面改修（RecallPhaseの分離）」に伴う、コンポーネントのライフサイクルと状態管理の齟齬が原因でした。

以前は `GameCanvas` 内の PixiJS の `app.ticker`（毎フレーム実行されるループ）に、以下のロジックが組み込まれていました：
「もし現在のフェーズが `idle` なら、1秒後に `startNextTrial()` を呼ぶ」

しかし、改修により `isMemorizing` の時のみ `GameCanvas` をマウントし、`phase === 'recall'` の時はアンマウントする仕様に変更されました。
そのため、リコールをクリアして `phase` が `idle` に遷移した瞬間に再び `isMemorizing` が `true` となり `GameCanvas` が再マウントされますが、マウント時点で既に `phase === 'idle'` となっているため、状態の**変化（差分）**を検知できず、上記の「1秒後の発火ロジック」が完全に無視される（空回りする）状態に陥っていました。

## 修正内容

コンポーネントの表示切り替え（マウント/アンマウント）に依存する古いPixiJS側のトランジションロジックを廃止し、Reactアプリケーションの最上位（`App.tsx`）で一元的にフェーズ遷移を管理するよう変更しました。

### `src/App.tsx`
- `useEffect` を追加し、`phase === 'idle'` 且つ `currentTrial > 0` の場合に、1秒のタイマー（`setTimeout`）で確実に `startNextTrial()` を発火させるようオーケストレーションを実装しました。

### `src/components/GameCanvas.tsx`
- 現在は使われていない不要なトランジションコード（`idle` 検知時の処理や `startNextTrial` の参照）を削除し、純粋に Memorize フェーズ（アニメーション描画）のみに専念するようクリーンアップしました。
